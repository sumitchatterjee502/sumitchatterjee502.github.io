## New Design Direction

### Concept: **"Signal / System"**

A technically sophisticated dark portfolio that feels like a well-architected system dashboard — precise, calm, and confident. Not a generic gradient template.

**Principles:**

- **Editorial hierarchy** — mono section labels, large Syne headings, generous whitespace
- **Restrained motion** — entrance fades only; no parallax, no particle effects
- **Data-forward hero** — verified metrics as the primary visual anchor
- **Structured density** — skills as categorized lists, not 40 identical cards
- **Project filtering** — domain tabs (Fintech, Insurance, IoT, Enterprise) using existing categories
- **Accessible contrast** — teal on navy meets WCAG AA for large text; muted text validated

**Design tokens (Tailwind):**

```
background:    #050d1a
surface:       #071525
surface-elevated: #0a1c30
border:        rgba(255,255,255,0.08)
accent:        #00d4aa
accent-blue:   #4da6ff
text:          #d8eaf8
muted:         #5e7e9e
heading:       #eaf4ff
```

**Typography:**

- `--font-display`: Syne
- `--font-body`: DM Sans
- `--font-mono`: DM Mono

**Signature element:** Subtle grid background in hero (carried from legacy) + thin accent gradient rule under section headings. No glassmorphism except a light nav blur.

### Sprint 6 — GitHub Pages Deployment

**Goal:** Automate build and deploy to GitHub Pages on push to main.

| Task | Details |
|------|---------|
| Create `.github/workflows/deploy.yml` | Node setup, install, build from `portfolio/`, upload `out/` |
| Configure GitHub Pages | Source: GitHub Actions |
| Verify static paths | All assets resolve at root (no basePath) |
| Test production build locally | `npm run build` + serve `out/` directory |
| Document deployment | Instructions in this README |
| First deploy | Push to main, verify live site |

**Workflow outline:**

```yaml
# .github/workflows/deploy.yml
on:
  push:
    branches: [main]
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  build:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: portfolio
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
          cache-dependency-path: portfolio/package-lock.json
      - run: npm ci
      - run: npm run build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: portfolio/out
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/deploy-pages@v4
        id: deployment
```

**Acceptance criteria:**

- Push to `main` triggers deploy
- Site live at `https://sumitchatterjee502.github.io/`
- All sections, links, and assets work in production

## GitHub Pages Deployment

### Fix: site shows README instead of portfolio

If [sumitchatterjee502.github.io](https://sumitchatterjee502.github.io/) shows the migration README, GitHub Pages is deploying the **repo root** (Jekyll + `README.md`) instead of the Next.js build.

**Fix (one time):**

1. GitHub repo → **Settings** → **Pages**
2. Under **Build and deployment** → **Source**, select **GitHub Actions** (not “Deploy from a branch”)
3. Push to `main` or re-run **Deploy to GitHub Pages** under **Actions**

The workflow builds `portfolio/out/` and publishes that artifact. The root `README.md` is documentation only — it is not the live site.

### Prerequisites

1. Repository settings → Pages → Source: **GitHub Actions**
2. Push workflow from Sprint 6
3. Ensure `portfolio/next.config.ts` has `output: "export"`
4. Optional: GitHub secret **`CONTACT_API_URL`** for the contact form API (Render deploy)

### Manual deploy (if needed)

```bash
cd portfolio
npm ci
npm run build
# Upload contents of portfolio/out/ to gh-pages branch or use workflow
```
